# Data Model

## PostgreSQL Source Of Truth

MVP stores metadata and artifact blobs in PostgreSQL.

MVP stores artifact bytes in `artifact_blobs.content bytea`.

S3-compatible object storage should be added soon after the MVP for larger archives. RustFS is the preferred S3-compatible target to keep self-hosting simple. The public API must not depend on whether blobs are stored in PostgreSQL or object storage.

Use `sqlc` with `pgx` for SQL-first type-safe database access.

Use UUID v7 primary keys for core tables. IDs are generated by the application so inserts can be batched and tested consistently.

All timestamps use PostgreSQL `timestamptz` and are serialized at API boundaries as UTC RFC 3339 timestamps.

```sql
  id uuid primary key,
  slug text unique not null,
  display_name text not null,
  description text,
  visibility text not null default 'private',

  updated_at timestamptz not null
```

```sql

  org_id uuid not null references organizations(id),
  slug text not null,
  display_name text not null,
  description text,
  visibility text not null default 'private',
  owner_team_id uuid,
  created_at timestamptz not null,
  updated_at timestamptz not null,
  unique(org_id, slug)
```

```sql
  id uuid primary key,
```

```sql
  id uuid primary key,
```

```sql
  content_type text not null,

  target_path text,
  created_at timestamptz not null,
```

```sql
artifact_blobs (
  digest text primary key,
  content bytea not null,
  size_bytes bigint not null,
  created_at timestamptz not null
```

```sql
artifact_locations (
  digest text primary key references artifact_blobs(digest),
  storage_driver text not null default 'postgres',
  storage_uri text,
  created_at timestamptz not null
)
```

For MVP, `artifact_locations.storage_driver` is `postgres` and `storage_uri` is null. This table reserves the migration path to S3-compatible storage without changing artifact file references.

```sql
  package_version_id uuid not null references package_versions(id),
```

```sql
package_search_documents (
  package_id uuid primary key references packages(id),
  latest_published_version_id uuid references package_versions(id),
  search_text tsvector not null,
  labels_json jsonb not null default '{}'::jsonb,
  artifact_types text[] not null default '{}',
  tool_names text[] not null default '{}',
  lifecycle text not null,
  visibility text not null,
  updated_at timestamptz not null
)
```

`package_search_documents` is a denormalized PostgreSQL full-text search projection. It can be maintained transactionally during publish/metadata updates or rebuilt by a maintenance job.

## Required Constraints

- `organizations.slug`, `namespaces.slug`, and `packages.name` must match `^[a-z0-9][a-z0-9-]{1,62}[a-z0-9]$`.
- `packages.name` is unique within one namespace, not globally.
- `package_versions.version` is unique within one package.
- `package_versions.version` must be strict SemVer in `MAJOR.MINOR.PATCH` form for published versions.
- Organization, namespace, and package slugs are immutable in the MVP.
- Visibility values are `private`, `internal`, and `public`.
- Effective visibility is computed as the most restrictive value across organization, namespace, package, and version.
- API tokens store hashes only; raw tokens are shown once at creation time.
- Published versions must have a non-null `digest` and `published_at`.
- Published versions must reject changes to manifest, artifact files, artifact blobs, version, and digest.
- Published-version immutability is enforced by application checks for friendly API errors and PostgreSQL triggers/constraints for safety.
- The `@latest` alias is a mutable pointer that updates automatically when a new version is published.
- Package version digest covers canonical manifest JSON plus sorted artifact paths, artifact types, target paths, file digests, and file sizes.
- Uploaded archive bytes are not part of package identity; uploads are normalized into artifact rows and blobs.
- Enforce configurable max artifact file size, max unpacked package size, and max artifact count.

- `package_versions(package_id, version)`

- `project_artifact_installs(project_id, package_id)`
- full-text index over package display name, description, labels, artifact paths, and manifest JSON

## Search Rules

- MVP search uses PostgreSQL full-text search.
- Default search results include published active packages only.
- Deprecated packages are included only when explicitly filtered and authorized.
- Draft, review, yanked, and archived versions are excluded from normal discovery.
- Search indexes package slug, display name, description, labels, artifact paths, artifact types, compatibility tools/runtimes/models, and maintainers.
- Artifact file contents are not indexed in MVP.

## Adoption Reporting Rules

- Adoption data is reported by CLI commands such as `install`, `check`, and `update --apply` when configured with a token.
- Reports contain lockfile summaries, not raw artifact content.
- Public package adoption dashboards show aggregate counts by package version by default.
- Detailed project identity is visible only to authorized org/package users.

## Migration Rules

- Use `golang-migrate/migrate` with numbered SQL migrations in `migrations/`.
- Migrations are SQL-first and are the schema source of truth.
- The server may run migrations at startup only when explicitly enabled for local development or tests.
- Production migrations run as an explicit command or deployment job before starting application instances.
- Down migrations should be provided for local development when safe; destructive production rollback remains an operational decision.

## Database Test Rules

- Migration and constraint tests run against real PostgreSQL.
- SQLite substitutes are not acceptable for DB integration tests because PostgreSQL-specific constraints, triggers, arrays, JSONB, and locking behavior matter.
- Tests may use a configured PostgreSQL URL or testcontainers once the test harness exists.
